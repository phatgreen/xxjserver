**1.1 — `gm/gmquery.php`** — 16 queries raw string → prepared statements
- `mysqli_prepare()` + `mysqli_stmt_bind_param()` (mysqli, not PDO)
- All `$_POST` variables sanitized via `intval()` or bound params

**1.2 — `game.php`** — 3 raw `$sid` in DELETE/UPDATE → prepared statements
- Also fixed operator precedence bug: `!$ym==''` → `$ym != ''`

**1.3 — `game/zbinfo.php`** — INSERT/UPDATE with raw `$sid` → prepared statements
- Uses `rowCount()` for success check instead of `exec()` return

**1.4 — `class/player.php`** — 13+ legacy functions converted
- `getguaiwu()`, `getyboss()`, `getmid()`, `getplayerrenwu()`, `changerwyq()`

### Group 2: Authentication (CRITICAL)

**2.1 — `index.php` + `reguser.php`**
- `reguser.php`: `password_hash($userpass, PASSWORD_BCRYPT)` on register
- `index.php`: `password_verify()` on login
- Auto-migration: plaintext passwords re-hashed on successful login
  ```php
  if (strpos($user['userpass'], '$2y$') !== 0) {
      $stmt = $dblj->prepare('UPDATE userinfo SET userpass=? WHERE username=?');
      $stmt->execute(array(password_hash($userpass, PASSWORD_BCRYPT), $username));
  }
  ```

**2.2 — `gm/gmquery.php` + `gm/config.php`**
- Hardcoded `'vingame'` → `GM_CODE_HASH` constant (bcrypt hash)
- `password_verify($gmcode, GM_CODE_HASH)` for verification
- Hash generated: `echo password_hash('vingame', PASSWORD_BCRYPT)`

### Group 3: Race Conditions (HIGH)

**3.1 — `game/quydoi.php`** — Currency exchange double-spend
- Full transaction: `beginTransaction()` → `FOR UPDATE` lock on player row + exchange log
- Atomic MT deduction: `UPDATE game1 SET uczb = uczb - ? WHERE sid = ? AND uczb >= ?`
- Daily limit checked inside transaction

**3.2 — `class/function/club_treasury.php`** — Treasury claim double-claim
- Atomic claim: `UPDATE ... SET claimed_by = ? WHERE id = ? AND claimed_by IS NULL`
- `rowCount() === 0` → already claimed

**3.3 — `game/club_boss.php`** — Boss HP deduction race
- Atomic: `UPDATE club_boss SET boss_hp = GREATEST(0, boss_hp - ?) WHERE id = ? AND boss_hp > 0`
- Actual HP read after update for kill check

**3.4 — `game/club.php`** — Club upgrade resource deduction race
- UPDATE with WHERE guard: `WHERE clubid = ? AND clubyxb >= ? AND clubczb >= ? AND clubexp >= ?`
- `rowCount() === 0` → resources depleted by another request

### Group 4: Critical Logic Bugs (CRITICAL/HIGH)

**4.1 — `class/player.php:2145`** — Pet infinite loop
- Bug: `for ($i=0;$i<$rangeslv;$i++)` — `$rangeslv` is ARRAY, cast to int = 1
- Fix: `$rangesCount = is_array($rangeslv) ? count($rangeslv) : intval($rangeslv); for ($i=0; $i < $rangesCount - 1; $i++)`

**4.2 — `game/tupo.php:163`** — Level 0 from breakthrough failure
- Bug: `$player->ulv = $player->ulv - 1` with no guard
- Fix: `if ($player->ulv > 1) { $player->ulv = $player->ulv - 1; ... }`

**4.3 — `game/club.php`** — No member cap on join
- Added: Check `club_benefits_config` max members before INSERT
- Counts approved members (`uclv > 0`), blocks if at cap

**4.4 — `game/club.php`** — Master leaves orphan club
- Master (uclv == 1) now blocked from leaving
- Must transfer leadership (renzhi) or delete club first

**4.5 — `game/club_boss.php`** — Pet damage calculated but not applied
- `$totalDmgToBoss = $damage + $petDamage;`
- Applied to boss HP and damage stats

**4.6 — `game/club_boss.php`** — Boss damage calculated but not applied to player
